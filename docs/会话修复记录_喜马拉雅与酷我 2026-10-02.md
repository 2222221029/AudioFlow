## 1. 会话背景

- **项目**：AudioFlow（多平台有声书下载器，含 Web/PWA 界面）
- **起始问题**：`https://www.ximalaya.com/album/78072071` 用网页版接口下载报错
- **专辑性质**：七猫中文网《山野诡闻笔记》，共 **1153 集**，
  **前 45 集免费试听，第 46 集起单集付费（0.2 喜点/集，会员免费）**
- **核心难点**：喜马拉雅 2026 年起给网页接口加了反爬指纹（webtk/HWWAF），
  付费集匿名只能拿到 90 秒试听片段。

---

## 2. 问题一

### 症状
网页版接口下载该专辑提示错误；`web_api` 章节接口匿名直连返回
`{"ret":407,"msg":"webtk缺失"}`。

### 根因（实测确认）
| 现象 | 实测结果 |
|---|---|
| `revision/album/v1/getTracksList` 匿名直连 | `ret=407 webtk缺失`（需浏览器会话指纹） |
| 指纹补齐后（HWWAFSESID 等） | 变为 `ret=401 用户未登录`（需登录态） |
| 付费集 `mobile/redirect/free/play/{id}/96` 匿名 | 302 → `..._preview_1124904.m4a`（仅 90s 试听、约 1.07MB） |
| 免费集（1–45）同一接口 | 302 → 完整 `aacv2-96K.m4a`（约 5.5MB） |
| **真实有效账号 Cookie** 后付费集同一接口 | 302 → **完整文件**（约 5.6MB） |

**结论**：接口本身支持按 Cookie 授权；匿名/无效凭据一律给试听。代码原行为把
1MB 试听当成功存盘（静默假成功），是"下载出错"的直接原因。

### 修复（提交 f0fcddf）
1. **web_api 章节接口**（`core/ximalaya_manager.py`）
   - 新增 `_warmup_web_fingerprint()`：请求前先访问 `revision/time`，把
     HWWAF 指纹 Cookie 装进 session（一次性、失败不阻塞）
   - `getTracksList` 请求头合并登录 Cookie + 会话指纹
2. **旧版直连**（`core/ximalaya_download_manager.py` `_download_m4a_direct_api`）
   - 补官方取流参数 `?device=android&isAsc=true` 与 `Cookie2: $Version=1`
   - Cookie 改为合并登录 Cookie + 会话指纹（`_web_cookie_header()`）
   - 新增 `_is_legacy_preview_url()`：redirect 终点 URL 含 `_preview` →
     判定付费试听，**拒绝存盘**并归类 `restricted`
3. **网页授权通道**（`_download_web_authorized`）
   - 解密出的 URL 若含 `_preview`：匿名提示"登录 Cookie 未生效"，
     有 Cookie 无权限提示"账号没有完整播放权限"

## 3. 问题二

### 症状
除网页版接口外的其他喜马拉雅通道也不可用，且部分**静默失败（错误信息为空）**。

### 根因（全通道实测，匿名态）
| 通道 | 修复前行为 |
|---|---|
| 电脑版接口（自动最高音质） | 四档全受限（未登录）→ 每档降级后清空 error → **静默失败** |
| MP3 档位 | v3/baseInfo 被风控 `ret=1001`，无兜底 → 失败 |
| MP3 解密 URL | 付费集解密出 `_preview` 却照常下载残缺文件 |
| 网页版付费集 | 旧版直连识别受限后仍去试授权通道，遇风控把"未登录"
  掩盖成"系统繁忙 ret=1001" |

### 修复（提交 f297fe1）
1. **PC 自动链**：保留最后受限原因，整链失败时给出可读错误
   （"PC 通道全部档位不可用：…未登录…"），不再静默
2. **网页版兜底**：
   - 匿名（无 Cookie）时受限直接返回，不再去试授权通道；
   - 提示追加"未配置网页登录 Cookie，无法获取付费集完整音频"
3. **MP3 通道**：
   - 补齐网页会话指纹 warmup + Cookie 合并
   - v3/baseInfo 被风控/空 playUrlList/解密失败 → 兜底旧版直连
     （`_mp3_fallback_to_legacy()`，按真实容器纠正扩展名）
   - 解密 URL 含 `_preview` → 拒绝存盘，归类 `restricted`

## 4. 问题三

### 症状
「无损优先（自动降级）」等移动端 V4 档位失败，提示"缺少已登录 App 实际
请求头中的 x-tk"；「无损优先（FHQ WAV）」字样也能完整下载。

### 根因
- 移动端 V4（无损/杜比/菁彩声）**只能认 App 票据 x-tk**，网页 Cookie 无法替代；
- 但用户只有网页 Cookie 时，「无损优先（自动降级）」应降级到**同样能拿到高
  码率的电脑版通道（256K）**，而不是整档失败；
- 测试中发现"无损优先（FHQ WAV）"少了「网页」二字会被 `_mobile_quality_profile`
  模糊匹配成移动端无损档——精确档位名不受影响。

### 修复（提交 e593caf）
`core/ximalaya_download_manager.py` `download_audio_by_quality`：
- 「无损优先/杜比/菁彩声」等 V4 音质优先链，在
  `未配置移动端凭证 && 有网页登录态` 时，**先试电脑版通道**（实测免费/付费集
  均可用、256K），成功即返回；失败再回 V4 链
- 与「移动端自动最高音质」既有回退语义对齐：仅凭证缺失时降级，
  网络/风控错误不降档

## 5. 功能

### 需求
酷我听书追更场景：某章节**先发布 128K MP3**（被订阅下载），服务端**后补无损**。
程序应自动检测并把该章节升级为无损。

### 设计（提交 4f93227）
原有 `diff_chapters` 只要本地文件存在就跳过 → 低码率文件永远升不了无损。
按五层打通：

| 环节 | 文件 / 方法 | 说明 |
|---|---|---|
| ① 探测 | `kuwo_manager.peek_best_available_format()` | 探测远端当前最高可用格式（FLAC 判定）；带短 TTL 缓存（10 分钟），避免每轮检测打接口风暴 |
| ② 记录 | `download_worker` 酷我分支 | 下载成功后写 `_delivered_format/_delivered_bitrate/_delivered_extension` |
| ③ 持久化 | `subscription_manager.mark_download_results` | 写入订阅状态 `delivered_quality` |
| ④ 检测 | `subscription_manager.diff_chapters` | 期望无损 + 本地交付非无损 → 探测远端有 FLAC → 章节以 `quality_upgrade` 原因进入缺失并标记 `_upgrade_quality`；**无音质记录的旧库章节跳过探测**（避免升级功能上线对几百上千集触发探测风暴）；文件数兜底/按数量推断均不再剪掉升级章节 |
| ⑤ 重下 | `download_worker` | `_upgrade_quality` 章节删除旧文件后强制重下（绕过"文件已存在跳过"分支） |

### 使用说明
- 订阅设置选**无损**（酷我默认即"优先无损"）后生效；
- 老库已下载章节自下次实际重下时开始记录音质；已有记录且非无损的章节，
  追更检测发现远端出现 FLAC 后自动发起一次升级重下替换。

## 9. 安全提醒

会话中曾使用真实喜马拉雅账号 Cookie 做授权验证（含 `1&_token` 登录票据 =
账号钥匙）。请务必：

1. **在喜马拉雅网页端退出登录后重新登录**，使该票据失效；
2. 排查 Cookie 是否泄露到他处；
3. 本仓库代码未写入任何真实凭证（凭据仅在测试时经环境变量/临时文件传入，
   已清理）。
