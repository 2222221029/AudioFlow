## 7. 终局结论：喜马拉雅网页通道在纯 Python 下载端不可用（2026-10-03 深夜实测）

> 用户提供真实网页登录 Cookie（uid=340500784，SVIP）后，用同一 Cookie 做对照实测，
> 网页通道的最终裁决如下。

### 7.1 实测对照（同一真实 Cookie，同一环境）

| 请求 | 结果 |
|---|---|
| 章节接口 `getTracksList`（带 Cookie） | `ret=407 WFP存在但校验失败` |
| 播放接口 web v3 baseInfo 130326634（带 Cookie） | `ret=1001 系统繁忙`（全档位一致） |
| 播放接口 web v3 baseInfo **78072071 对照专辑**（带 Cookie） | **同样 `ret=1001`** — 与专辑无关 |
| 播放接口 web v3 baseInfo（**匿名**，无 Cookie） | `ret=0` 但防盗链内容 `playUrlList` 恒空 |
| 页面/`revision/time` 下发 | 只有 HWWAFSESID/HWWAFSESTIME；**主页不下发 wfp** |

### 7.2 根因

- 网页登录态请求强制校验 **`wfp` 指纹**：该指纹由页面 JS 按浏览器环境（UA/IP/会话）
  **生成并强绑定**；用户 Cookie 里自带的 `wfp=...` 换环境即失效（`WFP存在但校验失败`）；
- 纯 Python 下载端（AudioFlow 容器 / 本沙盒）**无法运行网页 JS 重新生成 wfp**；
- 于是带登录态的网页接口请求恒被 407/1001 拦截；匿名不校验指纹但防盗链内容不放地址。

**这是服务端设计（账号+指纹+环境三者绑定），不是项目代码缺陷，无法通过改代码修复。**

### 7.3 三通道最终裁决（全部实测）

| 通道 | 裁决 |
|---|---|
| 电脑版 download/v2 | 版权方关闭下载：「该内容暂不支持下载！」 |
| 网页 v3（登录态） | **WFP 指纹风控 407/1001**，纯 Python 无法通过 |
| App V4（x-tk） | TME 密文 DRM，不实现绕过 |
| 酷我听书 60135077（TME 自家） | ✅ 明文 MP3/FLAC，本会话已修复并验证整本可下 |

### 7.4 代码改进（仍并入 v1.0.36）

- `_request_web_track_info`：`ret=407 WFP存在但校验失败` 终态不再静默重试，
  明确报 `restricted`：「网页指纹由浏览器 JS 按环境生成并强绑定，纯 Python 下载端
  无法通过校验；请在浏览器内登录试听，或改用其他通道」——用户升级后不再看到
  误导的「系统繁忙」。
- 全量测试 890 passed；预检工具 `scripts/ximalaya_web_cookie_probe.py` 实测输出：
  `restricted=网页Cookie未生效（currentUid=0）`（假 Cookie）与
  `接口失败: WFP 指纹风控`（真 Cookie）。

### 7.5 安全提醒

- 用户 Cookie（含 `1&_token` 票据）在本会话中经对话明文传输，**务必在喜马拉雅

## 8. 逆向突破：网页通道两级风控打通（wfp = 数美 openId，2026-10-03 深夜）

### 8.1 复盘
用户要求「模拟浏览器生成指纹」打通喜马拉雅网页版接口。从 wfp cookie 样本入手逆向：

1. 解码 wfp 样本（40 字符 base64）无明文结构，锁定页面 JS：`f714bf.js` 中
   `window.$ats.getOpenId().then((e) => cookie.set("wfp", e, …))` —— **wfp = 数美 ATS
   SDK（ats.2.5.7.js）的 openId**；`$ats.init({ channelId:"xmweb_www", domain:
   "https://www.ximalaya.com/xuid-web-fireeyes" })` —— 喜马拉雅自代理了数美取号端点。
2. 用 Playwright + headless Chromium 打开喜马拉雅页面，让页面 JS 自行取号 →
   抓到真实协议：
   ```
   POST /xuid-web-fireeyes/report/v1?cid=xmweb_www&p=j&m=q&c=0&e=n&s=1&r={16随机}&t={unix秒}&v={sha1}
   body = base64url(AES-ECB(zlib(JSON.stringify(设备指纹))))
   RESP = {"code":"000","data":{"acid":"…","openid":"AC…","isnew":"1",…}}
   ```
   **openid 即 wfp，与本环境（IP/UA/设备指纹）绑定**——用户 Cookie 里带过来的 wfp
   是本机浏览器的，换环境必然 407。
3. 同时发现浏览器 API 请求**还必须带 `xm-sign` 请求头**（cadd&&sid，与 PC 通道同一
   数美 hdaa 上报链路）——缺它即「webtk缺失/WFP 校验失败」。
4. **端到端验证（沙盒，数据中心 IP，真实账号 Cookie）**：

   | 组合 | getTracksList |
   |---|---|
   | 登录 Cookie + 旧 wfp | `407 WFP存在但校验失败` |
   | 登录 Cookie + 本环境 wfp（无 xm-sign） | `407 webtk缺失` |
   | 登录 Cookie + wfp + **xm-sign 头** | **`ret=200`**，currentUid=340500784 识别 |
   | 同上（浏览器同环境复测） | 与 Python 完全一致 |

   `ret=200` 后内容层仍有 `riskLevel=1005`（数据中心 IP 信誉低 → 空章节）；同环境
   headless 浏览器结果一样 —— 证明与请求工具无关，**纯 IP 信誉**。用户 NAS（家庭
   宽带 IP，信誉正常）部署后该链路应可取到章节与播放地址。

## 9. 追加：NAS 部署后仍报 ret=76「数据不存在」的根因与修复（v1.0.38）

### 9.1 用户现象
NAS 部署 1.0.37 后下载《大奉打更人》仍失败：`API error ret=76: 亲，数据不存在哦`。

### 9.2 根因（代码定位）
- `ret=76 数据不存在` 是**旧版直连接口** `mobile/redirect/free/play/{id}/{level}`
  （`_download_m4a_direct_api`）对本专辑返回的——该接口对版权方限制的专辑直接
  判无数据（2026-10-03 实测匿名/登录态一致），与签名/wfp 无关；
- 用户下载**档位是默认/M4A 等普通档位**：`download_audio_by_quality` 的 M4A 分支
  直连旧接口 → ret=76 → 失败。**只要不走网页通道（wfp+xm-sign），这本专辑必然**
  **落回这里**。

### 9.3 修复（v1.0.38）
1. `_download_m4a_direct_api`：识别 `ret=76`（新增常量 `XIMALAYA_RET_DATA_NOT_FOUND`）
   归类 `restricted` 并给出明确指引（旧接口停供 → 用「网页无损优先」+ wfp 生成，
   或酷我听书 60135077），不再让用户看到误导性「数据不存在」；
2. M4A 普通档位自动兜底：旧直连返回 ret=76 且**已配置网页登录 Cookie** 时，
   自动升级试一次网页授权通道（`_download_web_authorized`）——用户不换档位，
   wfp 就绪时也能成功；无 Cookie 则保留 restricted 指引；
3. 回归测试 +2（restricted 文案 / M4A 升级），全量 **892 passed**。

### 9.4 用户侧两件必做
1. 拉取并部署 **1.0.38** 镜像；
2. **在 NAS 容器内生成 wfp**（网页通道前提，否则 baseInfo 依旧 1001/407）：
   ```bash
   docker exec -it audioflow bash -c "pip install playwright && playwright install chromium && python scripts/ximalaya_web_fingerprint.py --verify"
   ```
   输出 `ret=200` 且 `trackTotalCount=2654` 即网页通道就绪；
3. 下载任务音质选「网页无损优先」（或保持默认档位，依赖自动升级）。

## 10. 追加：扫码/手动 Cookie → 三端凭证 + 网页指纹一站式补全（v1.0.39）

### 10.1 用户需求
1. 扫码登录喜马拉雅时，自动补全移动端（App V4 x-tk + Cookie）、网页端、电脑端
   三端所需参数与 Cookie（此前扫码只落网页端 + 电脑端）；
2. 手动输入网页 Cookie 同样补全三端；
3. 扫码/保存后同时生成 **wfp 指纹**（网页通道二级风控之一）并预热 **xm-sign**；
4. 移除账号管理中「移动端专用添加 Cookie 的输入框」及相关代码（移动端凭证改为
   自动派生，无需手工粘贴）。

### 10.2 实现
| 层 | 改动 |
|---|---|
| `core/ximalaya_universal_login.py` | 新增 `persist_universal_credentials()`（既有 derive 提炼 + store 回调）、`bootstrap_ximalaya_credentials()`（三端派生 + xm-sign 同步预热 + wfp 后台生成，返回安全摘要）、`web_token_from_cookie()` |
| `core/ximalaya_web_fingerprint.py` | 新增：wfp（数美 openId）生成/落盘/读取模块（`fetch_wfp`/`ensure_wfp`/`ensure_wfp_async` 后台线程 + 单飞锁），无 playwright 时优雅返回未就绪 |
| `core/qr_login.py` | 扫码成功 emit_ok 改走 `bootstrap_ximalaya_credentials`（三端 + xm-sign + wfp），摘要进 session.extra |
| `src/server/web_server.py` | `POST /api/cookies` xmly 分支保存网页 Cookie 后自动三端补全（derived 摘要随响应返回）；**删除** `POST/DELETE /api/cookies/xmly/mobile-ticket`；`GET /api/cookies` 增 `has_wfp` 字段 |
| 前端 | 移除「移动版 V4 App Cookie」输入框/保存/删除按钮及 hooks（saveXimalayaMobileTicket/deleteXimalayaMobileTicket）与 CSS 死样式；凭证状态行新增「网页指纹：已就绪/未生成」pill |
| 测试 | `TestUniversalBootstrap` +3（token 提取 / 三端派生落盘+x_tk / 无凭证不抛错），全量 **895 passed** |

### 10.3 效果
- 扫码一次 → 网页 + 电脑版 + **移动端**（App Cookie 与本地签发 x-tk）三端自动就绪；
- 同一操作同步预热 xm-sign（hdaa 上报，秒级）并后台生成 wfp（需 playwright/chromium；
  未安装时返回「未生成」，可手动 `python scripts/ximalaya_web_fingerprint.py`）；
- 账号管理喜马拉雅卡片显示「网页登录 / 电脑版 / 移动版 V4 / 网页指纹」四枚状态标，
  不再需要手动粘贴移动端请求头。

### 10.4 全流程提醒
网页通道下载《大奉打更人》等防盗链专辑仍需：① 有效网页登录 Cookie（重新扫码即可）；

后重新扫码会自动后台生成）；③ 下载档位选择「网页无损优先」或依赖 M4A 自动升级。
