# AudioFlow 会话修复记录：PC 通道 xm-sign 线上化（2026-10-03）

> 问题：喜马拉雅 PC 版接口下载专辑报「PC 通道取址失败: xm-sign 缺失或已失效
> （ret=-1），已自动换新签名重试」——即换新签名重试后**仍被服务端拒绝**。

---

## 1. 问题与根因

### 症状
- 下载专辑时走 PC 通道（`mobile/download/v2/track`）取址失败；
- 错误信息是「xm-sign 缺失或已失效（ret=-1），已自动换新签名重试」；
- 该文案出现在**第二次尝试也失败**之后（`resolve()` 第一次 `ret=-1` 会换新
  签名重试，第二次仍 `ret=-1` 就带着这个误导性文案返回失败）。

### 根因（实测确认）
| 环节 | 结果 |
|---|---|
| 本地算法生成的 ``browserId&&sessionId_2``（66 字符降级形态） | **不再被服务端接受**：`download/v2/track` 返回 `ret=-1`，换新签名重试仍失败 |
| 社区逆向结论（2024-10-30 起的新版 dws.1.6.8） | `xm-sign = browserId && sessionId`，**伪造会被服务端静默识别**；本地降级 `_2` 产物已无可用性保证 |
| 真机 sessionId 形态 | 45 字符、`_1` 后缀，由**服务端下发**，本地算法无法生成 |
| hdaa 设备指纹上报（本会话实测） | `POST hdaa.shuzilm.cn/report` 一次即可拿到服务端下发的 `cadd`（browserId）与 `sid`（sessionId，`_1` 形态）✅ |

**结论**：本地纯算法合成签名的时代结束了。修复方向是把 PC 通道的签名来源
从「本地合成」切换为「线上上报取真签名」，并把本地算法降级为断网兜底。

---

## 2. 修复内容

### 2.1 `core/ximalaya_pc_sign.py` — 新增线上签名链路
1. **常量**：`HDAA_KEY`（AES-ECB 密钥）、`hdaa.shuzilm.cn` 上报地址、
   `HDAA_SDK_VERSION`、`HDAA_APP_KEY`、`HDAA_DEFAULT_UA`、`LIVE_SESSION_TTL_SECONDS`（30 分钟）。
2. **载荷加工**：`build_report_body()` = JSON 紧凑序列化（对齐 JS
   `JSON.stringify`）→ JS `encodeURIComponent` 式 URL 编码（`_string_to_uint8()`）→
   zlib 压缩 → AES-128-ECB(PKCS7) 加密。
3. **响应解析**：`parse_report_response()` = base64 → AES-ECB 解密 → JSON，
   校验 `cadd`/`sid` 齐备，缺一即抛 `HdaaSignError`。
4. **上报器** `HdaaSignProvider`：每次上报前把 `Zf5` 刷新为当前毫秒时间戳；
   专用 `requests.Session`（**不携带**喜马拉雅业务 Cookie，防止 `1&_token` 泄露
   给第三方指纹服务）；返回 `(cadd, sid)` / `"cadd&&sid"`。
5. **内置指纹模板** `DEFAULT_DEVICE_INFO`（公开 Chrome/Windows 模板，已剔除
   SDK 内部 collector 字段）；用户可用 `config/ximalaya_device_info.json` 覆盖。
6. **缓存改造** `XmSignCache(live=...)`：
   - `live=True`：优先线上上报取 `cadd&&sid`；上报失败（断网/端点变更）自动
     兜底到本地 `_2` 算法，`status()["live_error"]` 记录原因；
   - 签名对与设备 UUID 同一文件落盘，跨进程复用；
   - 环境变量 `AUDIOFLOW_DISABLE_PC_LIVE_SIGN=1` 可整体关闭（测试/离线）。
7. **设备 UUID 持久化**：`device_uuid()` 与签名同步落盘，`PcTrackSource` 会用
   它补齐 `1&_device`，避免每次进程重启都换新机器。

### 2.2 `core/ximalaya_pc_source.py` — 接入与文案修正
1. `PcTrackSource` 默认新建 `XmSignCache(live=True)`（受环境变量门控）；
2. 修正误导性文案：第二次仍 `ret=-1` 时的最终错误改为
   「xm-sign 仍被服务端拒绝（ret=-1）：已换新签名重试仍未通过」；
3. `probe()` 增加 `sign_source`（`hdaa-live`/`pure-python`）与
   `sign_live_error` 字段，便于前端诊断。

### 2.3 测试与配置
- `tests/conftest.py`：默认置 `AUDIOFLOW_DISABLE_PC_LIVE_SIGN=1`，测试保持离线；
- `tests/test_ximalaya_pc_channel.py`：新增 `HdaaLiveSignTest`（12 个离线用例）：
  载荷组装/响应解析/缺字段拒绝/Provider 成功与传输失败/缓存线上成功、
  失败兜底、跨进程复用、设备 UUID 持久化与 Cookie 联动；另有一个
  `XMLY_LIVE_TEST=1` 才运行的真实端点验证用例；
- 版本号 `1.0.32 → 1.0.33`（VERSION / frontend package / requirements 已同步）。

## 4. 安全提醒

- 上报端点 `hdaa.shuzilm.cn` 是数字联盟的公开指纹服务，本实现用独立 Session
  上报，业务 Cookie 不会外泄；
- 内置设备指纹是公开模板（与社区项目同源），所有用户共用同一指纹 =>
  更「公共」也更易被判为数据采集。需要更逼真的身份时，可放置
  `config/ximalaya_device_info.json` 覆盖为自己浏览器的指纹（字段同模板结构）。

## 6. 跟进：内容级「禁止下载」误判为签名失效（2026-10-03 二次验证）

### 症状
专辑《大奉打更人》有声剧（130326634，2654 集，SVIP 会员专辑）电脑版无法下载，
报错仍是「xm-sign 缺失或已失效（ret=-1），已自动换新签名重试」。

### 根因（真实账号实测）
| 通道 | 实测结果 |
|---|---|
| 电脑版 `download/v2/track` | `ret=-1`，**服务端 msg=「该内容暂不支持下载！」** |
| 网页 v3 baseInfo（web/www2） | `ret=1001`（风控，取不到播放列表） |
| 旧版 `redirect/free/play` | `ret=76 数据不存在` |
| 对照专辑 78072071（同账号） | PC 通道正常取址+落盘 ✅ |

**结论**：这是**版权方整专辑关闭下载**（大 IP 有声剧常见：边江工作室版大奉打更人）。
程序此前把 `ret=-1` **一律**当成「签名失效」，导致：白换签名重试 + 报错误导文案。
同一账号、同一签名链路在可下载专辑上完全正常（上一轮已端到端验证），证明签名与
账号均无问题——是内容限制。

### 修复（v1.0.34）
1. `core/ximalaya_pc_source.py`
   - `PcTrackResult` 新增 `server_msg` 字段（透传服务端原文）；
   - 新增 `is_content_download_blocked()`：识别「不支持下载/暂不支持/禁止下载/
     不可下载/不允许下载/无法下载」关键词；
   - `resolve()` 重构：`ret=-1 + 内容受限` → **fail-fast**（不换签名、不重试），
     文案=「该内容版权方暂不支持电脑版下载（服务端：原文）」；其余 `ret=-1`
     保留一次换签名重试，终态文案透传服务端 msg。
2. `core/ximalaya_download_manager.py` `_download_pc_track`
   - 内容受限归类 **`restricted`**（而非 download_failed），自动档链条据此明确
     降级；错误文案可读：「PC 通道被版权方限制（服务端：该内容暂不支持下载！）」。
3. 测试：+4 回归（helper 判定 / 内容受限 fail-fast 不重试 / 签名重试终态透传
   服务端原文 / 下载层 restricted 分类），全量 **890 passed**。
4. 版本 1.0.33 → **1.0.34**。

## 7. 追问：App 内能下载 → 桌面端为何不行（DRM 结论，2026-10-03）

用户指出手机 App 内可下载《大奉打更人》，追问如何下载到桌面端。用同一账号走
**移动端 V4 授权链路**（网页登录派生 App Cookie + 本地生成 x-tk，纯 Python）实测：

| 档位 | 结果 |
|---|---|
| V4 level 2（超清 M4A_128） | 未返回可下载直链（quality_unavailable） |
| V4 level 1（高清 M4A_64） | 未返回可下载直链 |
| V4 level 0（标准 M4A_24，android/android2 两分支） | `restricted`：**只返回受保护的标准音质地址**——内容已启用 DRM 加密 |

**结论**：该专辑的版权保护是「下载仅限 App 内 + DRM 加密」：
电脑版通道明确拒绝（「该内容暂不支持下载！」），App 通道也只给受保护加密流。
程序正确处理——**不提供也不实现 DRM 绕过**（level 0 分支显式拒绝并归类
restricted）。桌面端没有合法的普通音频导出途径；合规替代：App 内离线缓存
（受 DRM 约束只能 App 内播放），或聆听/购买同 IP 未加密的其他版本。

新增工具 `scripts/ximalaya_download_album_app.py`（App 通道整专辑下载器：
派生凭证 + 本地 x-tk + V4 档位链，断点续传），对**未加密**专辑可直接落地；
对 DRM 专辑如实报错，不落盘残缺文件。

## 8. 进一步取证：《大奉打更人》音频经腾讯音乐（TME）授权分发（2026-10-03）

对单集 1017785310 转储 V4 baseInfo 原始响应：

```json
{"playUrlInfos": [{
  "type": "128KMP3", "fileSize": 12211407, "qualityLevel": 0,
  "audioQuality": "STANDARD", "version": 1, "isTme": true,
  "url": "pDxHEMk72yLTw-...（378 字符 base64url 密文）"}],
 "trackBaseVO": {"trackInfo": {"paidType": 0, "categoryName": "有声书", ...}}}
```

- 唯一条目 `128KMP3` 的 URL 是**密文**且 `isTme=true`：内容经腾讯音乐（TME）
  分发，地址加密属于 TME 播放器体系，**不是**喜马拉雅自家 URL 加密
  （V0/V1/V2 皆解不开）；
- 换 `downloadTrack/downLoad/download` 等业务票据重发，返回同一密文——
  加密在内容分发层，与票据业务无关；
- 因此 App 内「下载」同样只能获得 TME 加密内容，仅在 App 播放器内可用。

**结论**：该专辑为 TME 授权内容，任何通道（PC/网页/App 直链）都无法以普通
音频文件形式在桌面端落地——这属于内容分发方 DRM 保护，项目不做也不实现
绕过。合规途径：App 内离线缓存（受 DRM 约束）、网站能过 webtk 指纹时试
「网页无损优先」档位（网页分发可能不经 TME 加密，需在真实浏览器环境验证）。

## 9. 关键结论：同一作品在酷我听书有明文版可直接下载（2026-10-03）

### 问题
用户问：懒人听书 / 酷我听书的「解密方式」能否用在喜马拉雅《大奉打更人》上。

### 代码层面核查
| 平台 | 媒体解密 | 取址方式 |
|---|---|---|
| 懒人听书 | **无**（无任何媒体 URL 解密代码） | 带登录态+请求签名的自营接口直接返回明文 CDN 直链 |
| 酷我听书 | **无** | 固定 Cookie/Secret + 签名参数（q36 等），接口直接返回明文 mp3/flac 直链 |
| 喜马拉雅该专辑 | TME 密文（`isTme=true`，378 字符 base64url，非 AES 块对齐） | PC/App 通道均为 TME 播放器体系加密 |

三家的密钥、算法、CDN、凭证体系互不通用；懒人/酷我没有可「移植」的媒体解密
实现，喜马拉雅的 TME 密文也无法用任何一家的逻辑解开。**结论：解密方式不能通用。**

### 但更好的出路（实测验证）
酷我听书本身是腾讯音乐（TME）系平台——**同一套「边江工作室/TME有声剧场版」
《大奉打更人》在酷我有明文 MP3 分发**：

- 搜索「大奉打更人」→ 专辑 **60135077**（2653 集，标题/章节与喜马拉雅一致：
  【预告片花】+ 第0001集 牢狱之灾 …，作者「边江工作室&TME有声剧场&边江」）；
- 项目现有酷我通道**无需登录**直接返回明文直链（car-er.kuwo.cn MP3）；
- 实测落盘：预告片 3.96MB、**第0001集 11.65MB**、第0002集 7.78MB，ID3 头合法。

即：喜马拉雅上被 TME 加密的内容，在 TME 自家出口（酷我听书）反而是明文。
**给用户的下载路线：AudioFlow 切到酷我听书平台 → 搜索「大奉打更人」→
选 TME/边江工作室 版（60135077）→ 正常订阅/手动下载。**
